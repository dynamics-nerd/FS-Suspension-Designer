### 4. Validaciones redundantes y límites de confianza

Composición privada canónica, validación agrupada de compatibilidades, ejecución/
anexado en una operación y pruebas locales de igualdad exacta reducen recorridos.

## Resource policy for measurements

Fresh owned MATLAB launchers, tracking their descendant processes only. Measure
private commitment, resident memory and aggregate private commitment separately.
Reserve max(768MiB,5% physical RAM). Initial runs used an aggregate private cap
of80% RAM free at launch. That cap stopped the first UI probe at2.53GB private
while1.76GB physical RAM was still free: private commitment is not resident RAM.
From before-storage onward the private cap is min(2×initial free physical RAM,
50% initial available commit), with the same independent physical reserve and
all inputs recorded in each sample. This is a diagnostic safety budget, not an
application history/candidate limit. Stop before exhausting available RAM; never
call a preventive stop an OOM or a proven leak. Do not close user processes.
Initial free RAM was approximately1.9GiB. The first profile driver errored in
its own result accumulation; later pre-optimization probes stopped during
BUILD/BUMP at the free-RAM reserve. These are retained, not PASS evidence.
The user closed what they could; a subsequent lower-overhead core-only launch
uses -nojvm, with startup mode stated in its measurements. UI/worker acceptance
must run normally, not be inferred from the no-Java diagnostic.
