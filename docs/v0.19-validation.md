## Architecture and admitted physical coverage

Value-only `fsd.packaging` owns definitions, analytic distances, stored-state
resolution, evaluation, algebraic validation and plotting. `fsd.project` owns
versioned optional resources, explicit scenarios, evidence and canonical staleness.
`fsdui` owns presentation parsing/drafts and calls the core. The process worker
retains all engineering/file operations; backgroundPool performs only reversible
plain-data conversion. Existing snapshots/epochs/cancel/single-writer publication
guards apply across ENCODING/EXECUTING/DECODING.
No additional service, language or mandatory Navigation dependency.

Production geometry: sphere/capsule/AABB/OBB with proper frames, explicit radii
or boundary diameter conversion, tube centreline endpoints and material/free
space roles. Six unordered pair families use analytic centreline minima,
piecewise quadratic segment/box and SAT+vertex/edge box separation. AABB broad
phase is only conservative culling; exact reported separation requires narrow
phase. Distances are unsigned, intersecting sets have distance0, and overlap
witnesses/depth are not fabricated. See the contract for equations and fields.

Project/GUI motion: one corner, NOMINAL or actual stored BUMP requests in order.
Failed/missing source states, unsupported shapes and absent physical dimensions
remain visible and prevent CLEAR. Independent tests include genuine native
reflection and RACK-corner inner motion at the resolver boundary; that does not
claim a complete RACK sweep workflow. Fixed/inside/outside point regions and
exact local-joint exceptions are persisted and visible. Seed/candidate/adopted
registry geometry is checked separately from historical objective/eligibility.

Runtime toolboxes actually exercised: the unchanged native kinematics uses its
existing Optimization Toolbox path; Parallel Computing Toolbox supplies the
owned process worker and isolated deterministic benchmark; Navigation26.2 is
used only for optional API/oracle tests. Base MATLAB owns the production finite
primitive kernel. No Simscape, CAD import or replacement optimizer.

## Limits and OPEN DECISIONS

- Only declared simplified material/regions/pairs are covered. Hardpoints or
  effective rolling radius do not imply tire width, rim material/cavity, brakes,
  tube radius or an upright envelope. Free rim interior is never occupied mass.
- No exact mesh/cylinder narrow phase, arbitrary concave CAD, continuous swept
  collision, automatic adaptive solve/refinement, contact forces, FEA, fatigue,
  manufacturing or regulatory certification. Unsupported data is not a PASS.
- No integrated RACK/ROLL/combined motion, cross-corner moving assembly or
  dynamic actuation material bindings. New native/frame adapters and tests are
  required; endpoint existence is insufficient to invent those poses.
- Engineer chooses dimensions, source uncertainty/fidelity, local joint-contact
  decomposition, all physical margins and required pairs, frame assumptions,
  motion grid and refinement. Numeric budgets are not manufacturing allowances
  and do not propagate native pose or measurement uncertainty.
- CLEAR_SAMPLED means only evaluated declared samples/constraints. A tested
  collision between samples is intentionally missed, demonstrating the absence
  of a continuous guarantee. A detected collision may coexist with incomplete
  coverage; status and coverage must be read together.
- History/context validation and MAT serialization can be expensive. Coarse
  process asynchrony is supported; kernel parallelism stays disabled for the
  measured small-case overhead. Large-batch measurements are workstation/load
  specific, not a universal parallel threshold.
- Stored plotting validates the complete algebraic result, then renders on the
  MATLAB UI thread. Large-volume/large-grid interactive rendering has not been
  benchmarked as responsive; the process worker does not make graphics rendering
  asynchronous. The measured native interaction case uses three explicit solids
  and three BUMP samples, not a claim about arbitrary scene size.
- Async navigation is tested at actual worker-execution and response-decoding
  checkpoints, not by a continuously sampled event-latency bound. PCT submission/
  transfer, response acceptance and final rendering can still cost client-thread
  time for a gigabyte-scale history. Moving pure string conversion to threads
  does not establish that every instant of that transport remains responsive.
