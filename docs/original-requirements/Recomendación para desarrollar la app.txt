Sí. Para **tu proyecto concreto** te recomendaría empezar con **MATLAB como lenguaje/núcleo de cálculo + MATLAB App Designer para la interfaz de la primera versión + GitHub desde el primer día**. ## MATLAB vs Visual Studio Code

Hay una confusión importante aquí: **Visual Studio Code no es una tecnología para crear interfaces gráficas**. Es principalmente un editor/IDE. Puedes programar Python, JavaScript, C++, etc. con VS Code, pero necesitarías elegir además una tecnología de interfaz: PySide/PyQt, React, Electron, Tauri, .NET, etc.

Para tu V1, yo haría:

```text id="subff7"
MATLAB
│
├── Núcleo matemático
│   ├── Geometría
│   ├── Cinemática
│   ├── Dinámica
│   ├── Neumático
│   ├── Rules
│   ├── Packaging
│   ├── Optimización
│   └── Exportación Adams
│
└── MATLAB App Designer
    ├── Ventanas
    ├── Botones
    ├── Tablas
    ├── Sliders
    ├── Gráficos
    └── Visualización 3D
```

App Designer está pensado precisamente para construir aplicaciones interactivas en MATLAB. ([mathworks.com](https://www.mathworks.com/help/matlab/ref/appdesigner.html?utm_source=chatgpt.com))

Y tiene una ventaja especialmente interesante **ahora mismo**: desde MATLAB R2026b las aplicaciones de App Designer pueden guardarse como `.m + .xml` en lugar de obligatoriamente como `.mlapp` binario. Eso permite que Git pueda mostrar qué líneas han cambiado, hacer merges, comparar versiones, etc. ([mathworks.com](https://www.mathworks.com/help/matlab/creating_guis/app-designer-file-formats.html?utm_source=chatgpt.com))

Por tanto, si tienes R2026b, yo utilizaría **el formato plain-text de App Designer desde el principio**.

# FASE 3 — Tests. Desde aquí, obligatorios.

Aquí hay una diferencia entre hacer un trabajo de clase y desarrollar software de ingeniería.

Cada cálculo importante debe tener tests.

MATLAB incluye un framework específico para unit testing, por lo que puedes probar funciones, clases y posteriormente incluso componentes de App Designer. ([mathworks.com](https://www.mathworks.com/help/matlab/matlab-unit-test-framework.html?utm_source=chatgpt.com))

```text id="g6f934"

testDistanceConstraint.m
testCamber.m
testToe.m
testKPI.m
testRollCenter.m
...
```

Imagina que sabes que para una geometría:

```text id="r4nnfs"

```

Tu test comprueba:

```text id="ljewy4"
expected = -1.500;
actual = calculateCamber(...);

verifyEqual(testCase,actual,expected,...
            "AbsTol",1e-6)
```

¿Por qué es tan importante?

Porque dentro de seis meses puedes modificar `RotationMatrix.m` para implementar steering.

Sin querer rompes camber.

GitHub/Matlab ejecuta los tests:


Y sabes inmediatamente que has roto algo.

Eso es mucho más importante para esta aplicación que tener una interfaz bonita.
